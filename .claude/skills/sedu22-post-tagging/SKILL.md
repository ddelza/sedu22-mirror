# sedu22-mirror 게시글 교육과정 단원 태깅

`sedu22-mirror` 레포는 다음카페 게시글을 크롤링해서 `data/posts/<fldid>/<dataid>.json`에 저장해두고 있다. 각 게시글에 교육과정 단원 태그를 붙여서 `explore.html` 사이트에서 단원별로 검색할 수 있게 하는 게 목표다. 원래는 Gemini API(`tag.js`)로 했지만 무료 등급 한도가 너무 낮아서(하루 20건 수준) 실질적으로 끝나지 않는다 — 이 스킬은 Claude Code 자신이 직접 내용을 읽고 판단해서 훨씬 빠르게 마무리하기 위한 것이다.

## 작업 방식: 배치 단위로 처리한다

한 게시글씩 파일을 열고 닫으면 13,000건 넘는 글에 영원히 걸린다. 대신 이 스킬에 딸린 두 스크립트로 **묶어서** 처리한다:

1. `node scripts/next-batch.js [배치크기]` — 아직 `tags` 필드가 없는 글을 배치크기만큼(기본 40) 골라서 `scratch/batch.json`에 `{id, board, title, content}` 형태로 저장하고, 전체 남은 미태깅 건수를 출력한다.
2. **네가 `scratch/batch.json`을 읽고, 아래 "분류 규칙"에 따라 각 글을 판단한다.** 배치 전체를 한 번에 판단해서 `scratch/result.json`에 `[{id, tags, tagsNote}, ...]` 배열로 써라(Write 툴 사용).
3. `node scripts/apply-batch.js` — `scratch/result.json`을 읽어서 각 게시글 JSON 파일에 `tags`/`tagsNote`/`taggedAt`을 써넣는다. 이미 태깅된 파일은 자동으로 건너뛴다(안전장치).
4. **`node build-site-data.js`는 사용자가 명시적으로 요청하기 전까지 돌리지 않는다.** (2026-08-12부터 방침 변경 — 예전에는 배치마다 즉시 반영했지만, 사용자가 "내가 시키기 전에는 사이트 재빌드하지 말고 데이터만 쌓아둬라"고 지시함.) 태깅 결과는 `data/posts/*.json`에 계속 쌓이고, `curriculum/unit-correlations.json`(아래 "상관계수 테이블" 절 참고)도 계속 갱신하되, `site-data.js`/`explore.html` 반영과 git 커밋·푸시는 사용자가 "이제 반영해줘"라고 할 때만 한다.
5. 1~3을 반복한다(4는 보류). `next-batch.js`가 출력하는 "전체 남은 미태깅" 숫자가 0이 될 때까지, 또는 사용자가 그만하라고 할 때까지.

한 배치(40건)를 처리할 때마다 남은 건수를 사용자에게 짧게 알려주고 계속 진행해라. 수천 건 단위 작업이니 중간에 매번 "계속할까요?"라고 묻지 말고, 사용자가 멈추라고 하기 전까지는 계속 배치를 돌려라. 다만 세션이 길어져 context가 걱정되면 몇 배치마다 진행 상황을 요약해서 알려줘도 된다.

## 반복 패턴 발견 → 새 태그 제안 → 소급 재검토

배치를 진행하다 보면 "미분류"로 자꾸 빠지는데 사실은 공통된 성격을 가진 글 무리가 보일 수 있다(예: 과학 행사/과학실 관리/동아리 운영처럼 수업 단원은 아니지만 과학 교사 업무에 해당하는 글들). 이런 패턴을 알아차리면:

1. 사용자에게 새 태그(카테고리 또는 세부 항목)를 제안한다. 예시 몇 건을 근거로 들면 좋다.
2. 사용자가 OK 하면, 그 태그를 "분류 규칙"과 이 문서에 반영한다.
3. **지금까지 이미 태깅해둔 글들을 다시 훑어서 새 태그를 놓치지 않았는지 확인한다** — `apply-batch.js`는 이미 태깅된 파일을 건너뛰므로 쓸 수 없다. 대신 `node scripts/add-tags.js`를 쓴다: `scratch/add-result.json`에 `[{id, tags:[...추가할 태그만...]}, ...]` 형식으로 써두면(기존 tags는 그대로 두고 뒤에 이어붙임, 중복은 자동 스킵), 이미 지나간 배치들에도 새 태그를 소급 적용할 수 있다.
4. 다시 `node build-site-data.js`로 반영한다.

이렇게 몇 배치 진행하면서 태그 체계 자체가 점점 확정되어 가는 것이 정상적인 흐름이다 — 처음부터 완벽한 분류 체계를 세우려 하지 말고, 실제 글들을 보면서 다듬어라.

## 단원 간 연관성(상관계수) 테이블 — 2단계 최적화

위 "이름이 다른 단원끼리도..." 규칙을 매 글마다 133개 단원 전체를 놓고 판단하면 토큰이 많이 든다. 그래서 실제로 함께 태그되는 빈도를 근거로 "이 단원엔 보통 이 단원도 같이 붙는다"는 참고 테이블을 만들어 최적화한다. 단계를 나눠서 적용한다:

**1단계 (지금부터 누적 태깅 건수가 약 2,400건 — 즉 지금(2026-08-12 기준 415건)부터 배치 약 50회, 2,000건을 더 태깅할 때까지):**
- 지금처럼 매 글마다 `unit-index.json` 전체를 놓고 관련 단원을 폭넓게 검토한다(연관 단원 테이블은 참고하지 않는다).
- 다만 매 배치가 끝나고 `build-site-data.js`를 돌린 뒤, `node scripts/build-unit-correlations.js`도 같이 돌려서 `curriculum/unit-correlations.json`을 최신 상태로 갱신해둔다. 이건 그냥 지금까지의 태깅 결과에서 "어떤 단원끼리 같은 글에 몇 번 같이 태그됐는지"를 집계만 하는 것이라 가볍다.
- 이 단계의 목적은 테이블의 신뢰도(표본 수)를 쌓는 것 — 아직 판단에 쓰지는 않는다.

**2단계 (누적 태깅 건수가 약 2,400건을 넘은 뒤부터):**
- 단원 태그를 하나 붙이기로 판단했으면, 133개 전체를 다시 훑는 대신 먼저 `curriculum/unit-correlations.json`에서 그 단원의 연관 단원 후보(상위 3~5개)를 확인하고, 그중 실제로 그 글 내용과 맞는 게 있으면 추가한다. 후보에 없더라도 명백히 관련 있어 보이면(예: 새로 생긴 패턴) 여전히 전체 목록에서 찾아 태그해도 된다 — 테이블은 힌트일 뿐 판단을 제한하는 게 아니다.
- 이 단계에서도 계속 `build-unit-correlations.js`를 주기적으로(예: 5~10배치마다) 재실행해서 테이블을 갱신한다. 표본이 늘수록 연관성 추정이 정확해진다.

`curriculum/unit-correlations.json`의 계수는 co-occurrence 원시 횟수가 아니라 **overlap coefficient** (`두 단원이 같은 글에 함께 태그된 횟수 ÷ min(두 단원 각각의 전체 태그 횟수)`)로 정규화되어 있다 — 자주 등장하는 단원(예: 태양계)이 사실은 별로 안 겹치는데도 원시 횟수만으로 상위권을 차지하는 걸 막기 위함이다. 값이 클수록(최대 1.0) 두 단원이 강하게 같이 다닌다는 뜻.

## 참고 데이터: 단원 목록

`curriculum/unit-index.json`에 "연도(curriculumYear)|학교급(schoolLevel)|과목(subject)|단원명(unit)" 형태로 전체 133개 단원이 들어있다. 배치를 시작하기 전에 이 파일을 한 번 읽어서 기억해두고, 이후 배치들에서는 다시 읽을 필요 없다(내용이 안 바뀜).

## 분류 규칙

- 게시글의 게시판명(board)/제목(title)/본문(content)을 보고, `unit-index.json`에 있는 단원 중 가장 관련성 높은 것을 고른다.
- **개수 제한 없음.** 관련 단원이 여러 개 보이면 다 태그해라. **연도(2015/2022)든 학교급(중학교/고등학교)이든 경계를 넘나들며 중복 태그해도 된다** — 예를 들어 같은 주제가 2015판/2022판 단원명으로 둘 다 있으면 굳이 하나만 고르지 말고 둘 다 넣고, 중학교 내용과 고등학교 내용에 걸쳐 있으면 그것도 둘 다 넣어라. 확신이 안 서서 하나만 고를 필요 없다.
- **이름이 다른 단원끼리도 내용이 겹치면 같이 태그한다.** 위 항목이 "같은 주제의 연도/학교급별 이형(異形)"이었다면, 이건 그와 별개로 **애초에 이름부터 다른 두 단원이 내용상 밀접한 경우**다. 예를 들어 천체관측 행사 글이 망원경으로 행성도 보고 별자리도 봤다면 "태양계"뿐 아니라 "별과 우주"도 같이 태그하고, 롤러코스터나 낙하 구조물처럼 위치에너지↔운동에너지 전환을 다루는 글이면 "운동과 에너지"뿐 아니라(2015판 한정으로 별도 단원인) "에너지 전환과 보존"도 같이 태그한다. 기준은 동일하다 — 그 글이 실제로 그 단원의 성취기준 내용을 다루고 있으면 태그하고, 억지로 엮지 않는다.
- 반드시 `unit-index.json`에 있는 연도/학교급/과목/단원명 표기를 **정확히 그대로** 쓴다(새로 만들거나 줄여 쓰지 않는다).
- **"과학교사 업무" 카테고리**: 수업 단원 내용이 아니라 과학 교사로서의 업무/행정에 관한 글은 아래 형식으로 태그한다. `topic`은 다음 셋 중 하나:
  - `"과학 행사"` — 과학의 달, 과학경진대회/탐구대회/토론대회, 발명대회, 과학캠프, 체험학습 등 행사 기획·운영·홍보
  - `"과학실 관리"` — 실험실/기자재/약품/안전 관리, 감사 대비 등
  - `"동아리 운영"` — 과학 동아리·발명동아리 등 동아리 운영 조언/후기
  - `"교원연수"` — 직무연수·자율연수 등 교사 대상 연수 안내/모집 공지
  - `"학급운영"` — 담임/교과 교사로서 학급을 운영하는 글. 모둠·조 편성 방법, 자리배치, 학급 규칙 세우기, 보상제도(도장·강화물·스티커), 발표자 선정법, 경청 지도, 첫시간 자기소개/아이스브레이킹, 학급 게시판·환경정리, 학부모 상담, 생활지도·담임 업무 고민 등. 과학 수업 내용과 무관하게 "학급을 어떻게 운영할지"가 핵심이면 여기에 해당한다.
  ```json
  { "category": "과학교사 업무", "topic": "과학 행사", "confidence": "high" }
  ```
  이 카테고리는 단원 태그와 **동시에** 붙어도 된다 — 예를 들어 천체관측 행사처럼 특정 단원 내용(태양계)을 다루는 행사 글이면 단원 태그 + 이 카테고리 태그를 같이 넣는다. 반대로 순수 행정/운영 글(장소 추천, 규정 문의 등)이면 이 카테고리 태그 하나만 넣는다.
- **"스마트 수업도구" 카테고리**: 단원 내용보다 수업에 쓰는 스마트 기기/도구 자체(활용법, 사용 후기, 팁)가 글의 핵심 주제일 때 붙인다. `topic`은 다음 중 하나:
  - `"MBL센서"`, `"아두이노"`, `"앱/프로그램"`, `"생성형 AI 도구"`, `"AR/VR"`, `"교육용 단말기(태블릿/크롬북)"`, `"메이커/3D프린팅"`
  - DALL-E, ChatGPT, Playground, Prompt Hunt처럼 이미지·텍스트를 생성하는 AI 도구는 일반 앱과 구분해서 `"생성형 AI 도구"`로 붙인다(일반 웹앱/설문지 등은 `"앱/프로그램"`).
  ```json
  { "category": "스마트 수업도구", "topic": "MBL센서", "confidence": "high" }
  ```
  이 카테고리도 단원 태그와 동시에 붙을 수 있다 — 예를 들어 MBL 센서로 광합성 실험을 한 글이면 단원 태그(식물과 에너지 등) + 이 카테고리 태그를 같이 넣는다. 도구가 그냥 스쳐 지나가듯 언급만 되고 글의 핵심이 다른 데 있다면 억지로 붙이지 않는다.
- **"수업 방법론" 카테고리**: 특정 도구나 단원 내용이 아니라 수업을 설계·진행하는 방식(교수법) 자체가 글의 핵심 주제일 때 붙인다. `topic`은 지금까지 다음과 같고 앞으로 계속 늘어날 수 있다:
  - `"거꾸로 교실"` — Flipped Classroom(집에서 영상으로 예습, 수업시간엔 활동/토의) 관련 글. `거꾸로 교실(김신혜)` 게시판(fldid `5FKz`, 112건)이 전용 게시판이다.
  - `"IB(개념기반학습)"` — IB(International Baccalaureate) 교육과정, 개념기반 탐구학습(사실적/개념적/논쟁적 질문 등) 관련 글.
  - `"배움중심수업"` — 경기도 등에서 쓰는 학생 주도 활동 중심 수업 방식. 활동지 제목/본문에 "배움중심수업" 또는 "배움중심 수업 활동지"라고 명시적으로 나오는 글에 붙인다.
  ```json
  { "category": "수업 방법론", "topic": "거꾸로 교실", "confidence": "high" }
  ```
  다른 교수법(예: 하브루타, 프로젝트 수업 등)을 다루는 글 무리가 새로 보이면, 기존 방식대로 사용자에게 새 topic 추가를 제안하고 승인받은 뒤 반영한다(아래 "반복 패턴 발견" 절차 참고). 이 카테고리도 단원 태그와 동시에 붙을 수 있다.
- **"게시판별 분류" 카테고리는 AI가 판단할 필요가 없다.** 게시글의 `boardName`을 그대로 topic으로 붙이는 기계적 메타데이터라서 `node scripts/add-board-tags.js`가 전체 글에 한 번에 처리해둔다(이미 태깅됐든 안 됐든 상관없이 전체 적용, 재실행해도 안전). 배치 분류할 때는 이 카테고리를 신경 쓰지 않아도 된다 — `next-batch.js`/`apply-batch.js`도 이 태그 하나만 있는 글은 "미분류(미처리)"로 취급하므로 정상적으로 배치에 포함된다.
- 위 어느 것에도 해당하지 않는 글(순수 잡담, 교권/시국 관련 토로, 자유게시판성 글 등 수업 단원도 교사 업무/도구 활용/학급운영도 아닌 것)은 아래처럼 "미분류"로 표시한다(이때 다른 필드는 전부 null):
  ```json
  { "curriculumYear": null, "schoolLevel": null, "subject": null, "unit": "미분류", "confidence": "high" }
  ```
- `tags` 배열은 절대 비워두면 안 된다 — 아무 것도 매칭 안 되면 반드시 "미분류" 항목 하나를 넣는다.
- 각 태그에 `confidence`(`"high"|"medium"|"low"`)를 붙인다. 내용이 애매하거나 여러 단원/카테고리에 살짝씩만 걸치는 경우 `"low"`나 `"medium"`을 써라 — 무리해서 확신도를 부풀리지 마라.
- `tagsNote`는 왜 이렇게 판단했는지 한두 문장으로. 짧아도 된다.

## result.json 형식

```json
[
  {
    "id": "424t-127",
    "tags": [
      { "curriculumYear": "2015", "schoolLevel": "중학교", "subject": "과학", "unit": "물질의 구성", "confidence": "low" }
    ],
    "tagsNote": "왜 이렇게 판단했는지 짧게"
  },
  {
    "id": "424t-129",
    "tags": [
      { "category": "과학교사 업무", "topic": "과학 행사", "confidence": "high" }
    ],
    "tagsNote": "드론 날리기 행사 노하우 문의 — 단원 내용이 아니라 행사 운영."
  }
]
```
`id`는 `batch.json`에 있던 값을 그대로 복사해서 쓴다(형식은 `fldid-dataid`).

## 사이트 반영

`node build-site-data.js`(레포 루트에서 실행)를 돌리면 `explore.html` 사이트에 태깅 결과가 반영된다. 위 "작업 방식"에 적었듯 배치마다 즉시 돌려서 실시간으로 반영해라 — 마지막에 몰아서 하지 않는다.
